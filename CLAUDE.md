# cap-status-bar

Capacitor plugin for managing native status bar styling, visibility, colors, and overlays on iOS and Android.

## Project Structure

- `src/` — TypeScript source (plugin entry, type definitions, web fallback)
- `ios/Sources/CAPStatusBarPlugin/` — Swift native implementation
- `android/src/main/java/com/cap/plugins/capstatusbar/` — Java native implementation
- `example-app/` — Ionic/Angular example app
- `dist/` — Compiled output (generated by build)

## Tech Stack

- **Capacitor 8+** (peer dependency: @capacitor/core >= 8.0.0)
- **TypeScript** ~4.1.5 (strict mode, target ES2017)
- **Rollup** for bundling (IIFE + CJS)
- **Swift** (iOS 15.0+, CocoaPods via CapStatusBar.podspec, SPM via Package.swift)
- **Java 21** (Android, minSdk 24, compileSdk 36, Gradle 8.13)

## Architecture

Each platform follows a two-class pattern:
- **CAPStatusBarPlugin** — Capacitor bridge (routes JS calls to native, runs on UI thread)
- **CAPStatusBar** — Core implementation (status bar logic, color parsing, safe area)

### Plugin API Methods

`setStyle` · `show` · `hide` · `setOverlaysWebView` · `setBackground` · `getSafeAreaInsets`

### Key Types (src/definitions.ts)

- `Style` enum: LIGHT, DARK, CUSTOM
- `StatusBarAnimation` enum: NONE, FADE, SLIDE
- `StatusBarColor` type: hex string (`#RRGGBB` or `#RRGGBBAA`)

## Platform Notes

### iOS
- Requires `UIViewControllerBasedStatusBarAppearance = NO` in Info.plist
- Uses KVC for status bar control (avoids deprecation warnings)
- All UI operations dispatched to main queue

### Android
- API 29: deprecated SYSTEM_UI_FLAG methods
- API 30+: WindowInsetsController API
- API 35+: edge-to-edge with overlay views for status/nav bars
- All methods run on UI thread via `getActivity().runOnUiThread()`
